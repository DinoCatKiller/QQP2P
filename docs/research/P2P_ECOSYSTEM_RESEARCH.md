# 开源生态盘点：为什么"虚拟局域网"没有现成可嵌入库

> 调研时间：2026-08-24
> 关联文档：`docs/P2P_OVERLAY_RESEARCH.md`、`docs/P2P_LIBRARY_RESEARCH.md`
> 决策影响：支撑虚拟局域网方案"站在开源组件上自研编排层"的路线选择

---

## 一、调研问题

在确定了"任何软件互联"（虚拟局域网 / Overlay Network）的技术方向后，需要先回答一个前置问题：

> 开源世界里有没有"可嵌入的库"（像 rustp2p 之于 P2P 传输那样）可以直接提供虚拟局域网能力？
> 还是说能用的开源分享少到基本等于只能自研？

**结论先行：不是只有"从零手搓"一条路，但"开箱即用的可嵌入虚拟局域网库"在开源界确实极少——而且这种少是有结构性原因的。**

---

## 二、开源生态全景：虚拟局域网方案的四种形态

| 形态 | 代表 | 能不能嵌入我们的程序？ |
|---|---|---|
| ① 完整产品（独立程序/服务） | ZeroTier、Tailscale、Nebula、Netbird、n2n、tinc、**EasyTier** | ❌ 全是"软件"不是"库"，自带控制面/账号/服务端，只能外部调用 |
| ② 可嵌入 SDK | **libzt**（ZeroTier 官方嵌入版）、**EdgeVPN**（Go + libp2p） | ⚠️ 极少数，但都有硬伤（见第三章） |
| ③ 组件级库（自己拼装） | **wintun、rustp2p、quinn、iroh、tokio-tun** | ✅ 传输/打洞/TUN 都有成熟开源库，但"编排层"没有现成的 |
| ④ 全自研（连协议都自己写） | —— | 没必要，纯属重复造轮子 |

---

## 三、两个"看似能直接嵌"的，逐个掰开看

### 3.1 libzt（ZeroTier 官方 SDK，有 Rust 绑定）

| 维度 | 结论 |
|---|---|
| 许可证 | **BSL 1.1**（商业源许可，不是真开源——"免费内部使用"，商用受限，与"强力基建"的野心冲突） |
| 控制面 | 仍然绑死 ZeroTier 网络（公共 controller 或自建，等于还是用它的体系） |
| 形态 | Rust 绑定主要是 **Socket API**（进程内 socket），**不创建系统级 TUN 网卡** → 实现不了"任何软件透明互访" |

### 3.2 EdgeVPN（Go，基于 libp2p）

- 是"库"形态，但作者自己声明：**未安全审计、Gossip 协议对低延迟不友好、主要用于学习/实验**
- 而且是 Go + libp2p 技术栈，与 Rust 项目接不上

### 3.3 EasyTier（Rust，最接近的"表亲"）

- 2026 年最活跃的国产 Rust 组网项目，**LGPL-3.0** 许可，支持 UDP 打洞（含 NAT4-NAT4）、IPv6、子网代理，**不依赖公共服务器**
- 但是**完整程序形态**（`easytier` / `easytier-cli` 独立 exe），官方没有提供可嵌入的 Rust 库 API；LGPL 嵌入也要遵守条款
- 它的价值对我们不是"直接用"，而是**源码是最好的参考教材**（TUN 管理、NAT4-NAT4 打洞、路由表、IP 分配都是我们要写的）

---

## 四、为什么"这种分享很少"？——结构性的，不是偶然

| 原因 | 解释 |
|---|---|
| 技术栈太长 | 虚拟局域网 = TUN 网卡 + 协议栈 + 加密 + 打洞 + 控制面 + 平台兼容，是"最长"的网络软件之一，个人很难做完还开源 |
| 做出来就有商业价值 | ZeroTier（BSL）、Tailscale（闭源）都商业化；开源的（n2n/tinc/Nebula）多是独立工具形态 |
| 与 P2P 库的驱动不同 | rustp2p / libp2p / iroh 是"给开发者用的工具"，有社区贡献动力；虚拟局域网是"端产品"，用户直接用，**没有二次开发的诉求 → 就没有库化动力** |

**结论：P2P 传输层（rustp2p）开源得很热闹，但"虚拟局域网整体"的开源分享确实很少，且没有 Rust 可嵌入的成熟库。**

---

## 五、对决策的意义

本次调研确认了方案路线——**站在开源组件上自研"编排层"**，不是从零手搓：

```
wintun（TUN 网卡，成熟库）       ← 开源
rustp2p / quinn（加密+打洞传输） ← 开源
QQ 信令（控制面）                ← 已有
──────────────────────────────
缺的只有"编排层"：IP 分配、成员表、路由表、TUN 包 ↔ P2P 流映射
这层开源没有现成库，但代码量可控（几百行），
且正是"强力基建"的核心竞争力所在
```

这个结论其实很鼓舞：**组件全有开源可嵌，唯一要自己写的编排层恰是商业产品的护城河，开源界给不了——所以自研是对的，但不是"只有自研一条路"，而是"开源给了组件，护城河必须自己挖"。**

## 六、对实施的影响

- **N2 里程碑补充**：参考 EasyTier 源码实现（仅借鉴，不抄，规避 LGPL）——TUN 管理、NAT4-NAT4 打洞、路由表、IP 分配都以该源码为参考教材
- **路线1（装现成客户端）降级**：ZeroTier 保留为"兜底/快速原型"选项，不再作为主线——免费版 **10 台设备 / 1 个网络** 限制（2026 年已核实）+ 控制面依赖官方 Central（需账号 + API token）是硬伤
